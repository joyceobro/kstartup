## 2. 아이디어 기획 핵심내용 (요약)

- **대상 사용자**: 재무제표·담보가 없는 초기 벤처기업을 심사해야 하는 **기관 심사역** — 기술보증기금·신용보증기금·정책금융기관 보증/여신 심사역, 은행 기업여신 심사역, 액셀러레이터·창업지원기관 서류심사역. (개인 금융소비자 대상 앱이 아님)
- **해결하는 문제**: 초기 기업은 정량 데이터가 없어 기존 신용평가모형이 작동하지 않고, 심사역은 기업이 제출한 자기서술(사업계획서·IR 자료)에 의존하지만 이를 공개 기록과 교차검증할 시간·도구가 없다. 심사 결과의 대외 소명(심사위원회·내부감사·정책자금 국정감사) 부담도 크다.
- **제공 산출물 3종**:
  1. 출처 링크가 붙은 **3축 팩트시트** (기술력·투자이력·공신력) — 심사의견서에 그대로 첨부 가능한 형태
  2. **AI가 판정하지 않는 결정론적 집계 스코어** — 집계식·규칙 전면 공개, 원천값까지 역추적 가능
  3. 자기서술과 공개기록의 모순을 잡는 **6규칙 "확인 필요" 플래그** → 각 플래그를 **심층심사 질의 문항**으로 자동 변환
- **생성형 AI(Claude)의 역할**: 위 결정론적 팩트시트·플래그를 ① 심사의견서용 자연어 종합 서술로 옮기고 ② 각 플래그를 해당 기업 맥락을 반영한 질의 문항으로 다듬는다. **점수·등급 판정에는 관여하지 않는다.**
- **핵심 설계 원칙(Non-self-grading)**: 점수는 LLM의 판단이 아니라 공개데이터 원천값의 결정론적 집계다. 데이터 부재(재무·특허 없음)는 초기 기업의 정상 상태로 처리하고 처벌하지 않으며, 반증 엔진은 "없음"이 아니라 "모순"을 잡는다.
- **부가 데모**: 단계·업종·기술테마 태그 정합 기반의 투자자·후속 지원사업 힌트(룰 기반, 가상 시드 데이터임을 명시).

## 3. 문제 정의 및 제안 배경

### 3.1 현재 금융 서비스의 구체적 문제점

1. **초기 기업 심사에 쓸 정량 데이터가 없다.** 창업 3년 이내 기업 대부분은 외부감사·공시 대상이 아니어서 DART에 재무제표가 없고, 담보도 신용이력도 부족하다. 기존 신용평가모형·여신 스코어링은 이 구간에서 작동하지 않는다.
2. **심사가 기업 자기서술에 과도하게 의존한다.** 심사역이 받는 것은 회사가 작성한 사업계획서·IR 자료다. "AI 딥테크 기업", "투자유치 완료", "정부인증 보유" 같은 서술을 공개 기록(특허 원부, 벤처확인 공시, 인증 유효기간)과 대조해야 하지만, 접수 물량 대비 시간과 도구가 없어 육안 검토에 그친다.
3. **심사 판단의 대외 소명 부담이 크다.** 특히 정책금융·보증기관은 심사위원회·내부감사·국정감사에서 "왜 이 기업을 통과/부결시켰는가"를 근거와 함께 설명해야 한다. 판단의 출처를 사후에 재구성하기 어렵다.
4. **AI 평가 서비스가 오히려 리스크를 키운다.** 시중의 LLM 기반 기업평가 도구는 "이 회사 성장성 8점" 같은 점수를 모델이 직접 매긴다. 근거를 역추적할 수 없고, 환각 위험이 있으며, 심사 소명 자료로 쓸 수 없다.

### 3.2 특정 금융 고객과 채널 선택 배경

- **고객: 기관 심사역 (B2B).** 이 챌린지 주제("혁신·벤처기업의 다차원 성장성 평가")가 겨냥하는 실수요자는 개인 소비자가 아니라, 벤처기업을 상시 심사하는 보증·여신·창업지원 기관의 심사 담당자다. 이들은 ① 접수 기업 1차 스크리닝 ② 심층심사 질의서 작성 ③ 심사 판단의 근거 문서화라는 반복 업무를 안고 있고, 여기에 특화된 도구가 없다.
- **채널: 심사 업무용 웹서비스 (기관 내부 스크리닝 도구).** 오프라인 영업점 창구나 모바일 앱이 아니라, 심사역이 기업명(+주소)을 입력하면 즉시 3축 팩트시트와 질의서 초안을 돌려주는 웹 도구가 업무 흐름에 맞는다. 산출물이 심사의견서·질의서에 바로 붙일 수 있는 형태(출처 링크 포함)여야 한다는 점이 일반 금융 앱과 다르다.

## 4. 서비스 컨셉 및 차별성

### 4.1 핵심 컨셉

기업명(+주소) 입력 → 3개 공개데이터 소스 자동 수집 → 개체 연결(정규화) → **결정론적 3축 집계** → **6규칙 반증 엔진** → **생성형 AI 종합 서술 + 심층심사 질의 문항** → 심사의견서 첨부 가능한 근거형 리포트.

프레임 자체가 "이 회사 얼마나 좋은가?"가 아니라 **"자기서술이 공개 기록과 맞는가? 심사역은 어디를 더 확인해야 하는가?"**이다. 서비스는 심사를 대체하지 않고 근거 정리와 모순 지목까지만 하며, 최종 등급·여신 판단은 심사역과 심사위원회의 몫으로 남긴다.

### 4.2 기존 금융 앱·AI 평가 도구 대비 차별성

| 구분 | 기존 AI 기업평가 도구 | 근거 (본 서비스) |
|---|---|---|
| 점수 산출 주체 | LLM이 직접 점수를 매김 | **원천값의 결정론적 집계**. 집계식·규칙 전면 공개. LLM은 서술만 |
| 근거 추적 | 불가 (블랙박스) | 모든 점수·플래그에 원천 데이터 + 링크 부착, 역추적 가능 |
| 데이터 부재 처리 | "없음 = 저평가" | 초기 기업의 정상 상태로 중립 표기. 처벌하지 않음 |
| 이상신호 탐지 | 감점 | **"확인 필요" 플래그** + 심층심사 질의 문항으로 변환. 판단은 사람이 |
| 데이터 출처 | 유료·비공개 DB | **무료·안정 공개 API만** (KIPRIS·공공데이터포털·OpenDART). 재현·감사 가능 |
| 산출물 형태 | 요약 리포트 | 심사의견서·심층심사 질의서에 그대로 첨부 가능한 형태 |

### 4.3 평가 3축 (+ 보조)

| 축 | 데이터 근거 |
|---|---|
| 기술력 | 특허 출원/등록 건수, IPC 분류 다양성, 벤처확인 "연구개발유형" 여부 |
| 투자이력 | 벤처확인유형이 "벤처투자유형"인지 여부 (공시에 금액·시기 필드가 없어 이진 플래그로 근사) |
| 공신력 | 벤처확인 보유 여부 + 인증 유효기간 임박도 |
| (보조) 재무 | OpenDART — 있으면 표시, 없으면 "초기단계, 공시의무 없음" 중립 표기 |

### 4.4 반증 엔진 6규칙 (감점이 아니라 "확인 필요" 플래그)

- **A1** 연구개발유형 벤처확인인데 특허 0건 또는 장기 정체 → "R&D 성과물과 특허 계획을 확인"
- **A2** 특허 출원인이 법인이 아니라 대표 개인 명의 다수 → "법인 귀속(양도·전용실시권) 자료 확인"
- **C1** 벤처투자유형 인증 이후 특허·인증 활동 정체 → "투자금 집행·사업화 성과 확인"
- **C2** 벤처 인증 만료·임박한데 현재형으로 홍보 → "재확인 신청 진행 상황과 유효 인증서 확인"
- **D1** 재무 미확보 → DART 조회 후 "공시의무 없음" 중립 표기 (안 봄과 구분) + 재무 자료 요청
- **D2** 전 축 공백 → "근거 불충분, 판단 보류" 명시 + 기초 자료 요청

## 5. 활용 데이터 및 생성형 AI 모델 적용 방안

### 5.1 활용 데이터 종류 및 수집·활용 방안

| 소스 | 제공처 | 활용 축 | 수집 방식 |
|---|---|---|---|
| 특허·실용신안 (출원/등록, 권리상태, IPC) | KIPRIS Plus (한국특허정보원) | 기술력, 반증 A1·A2·C1 | REST `getAdvancedSearch` — 출원인명 검색, 개발단계 계정 트래픽 한도 → 결과 캐싱 |
| 벤처기업명단 (벤처확인유형, 유효기간, 지역·업종) | 공공데이터포털 (중소벤처기업부) | 투자이력, 공신력, 반증 C1·C2 | REST `odcloud` — 업체명 LIKE 필터, serviceKey 이중인코딩 방어 처리 |
| 단일회사 주요 재무지표 + 기업개황 | OpenDART (금융감독원) | 보조 재무, 반증 D1, 개체연결(사업자·법인번호) | 고유번호 XML 최초 1회 다운로드 후 기업명→corp_code 매핑 |

- **개체 연결**: 초기 스타트업은 대부분 사업자·법인번호가 공개되지 않아, 기업명 정규화(주식회사/㈜ 제거) + 주소 근사매칭을 기본 전략으로 쓰고, DART에 매칭될 때만 사업자·법인번호를 부가 식별자로 노출한다. 매칭 신뢰도(교차검증됨 / 기업명 매칭 / 매칭 실패)를 리포트에 함께 표기한다.
- **안정성**: 대회 배포 URL 생존 필수 구간(9/7~9/11)을 위해 데모 기업 조회 결과를 파일로 캐싱하고, 실시간 API가 막혀도 서비스가 죽지 않도록 모든 외부 호출을 예외 격리한다.
- **재현성**: 3개 소스 모두 무료·공개 API이며 집계식과 규칙을 코드에 공개해, 같은 입력에 같은 결과가 나오고 제3자가 감사할 수 있다.

### 5.2 생성형 AI 모델(Claude) 적용 방안 — "판정하지 않고 서술한다"

본 서비스의 점수·플래그는 **전부 결정론적 집계**이며, 생성형 AI는 그 결과를 사람이 읽고 쓸 수 있는 형태로 옮기는 데만 쓰인다. LLM이 "이 회사는 8점"이라고 매기는 구조를 의도적으로 만들지 않았다.

**모듈**: `core/narrative.py` — Claude(`claude-opus-5`) 단일 호출. 입력은 결정론 결과 JSON에서 추린 원천값(벤처확인 원문, 3축 tier·지표, 플래그 메시지)이며, 출력은 JSON 스키마로 강제된 두 필드다.

1. **종합 근거 서술 (summary)**: 3축 팩트시트와 확인 필요 플래그를 심사의견서에 첨부 가능한 건조한 실무체 3~5문장으로 요약한다. 이미 집계된 tier·수치를 인용만 하고 재판정하지 않으며, 심사역이 심층심사에서 확인할 지점을 사실 기반으로 짚는다.
2. **심층심사 질의 문항 다듬기 (questions)**: 6규칙 반증 엔진이 만든 템플릿 질의 문항을, 해당 기업의 실제 상황(인증 만료일, 특허 출원 시점 등)을 반영한 한 문장으로 자연스럽게 고쳐 쓴다. 결정론 템플릿은 그대로 보존해 LLM 호출 실패 시 fallback으로 쓴다.

**시스템 프롬프트에 하드 제약**: 점수·등급·투자적격 여부를 새로 판정·변경 금지, 입력 JSON에 없는 사실(매출·고용·경쟁사) 생성 금지, 데이터 부재를 결점으로 서술 금지, 확인이 필요하면 단정하지 말고 "확인 필요"로 명시.

**안전장치**: `ANTHROPIC_API_KEY` 미설정 또는 API 오류 시 서술 레이어는 `None`을 반환하고, 결정론적 3축 점수·반증 플래그·질의서 시드는 그대로 동작한다. 즉 생성형 AI는 서비스의 가치를 더하되, 그것이 없어도 서비스가 성립한다.

**향후 적용 확대**: 심사역이 기업 자기서술 원문(사업계획 요약·IR 텍스트 — 비정형 데이터)을 붙여넣으면, LLM이 주장(claim)을 추출해 공개 기록과 대조하고 새로운 모순 후보를 제시하는 단계. 현재는 벤처확인유형을 자기서술의 프록시로 쓰고 있어, 이 확장이 "비정형 데이터 분석"을 정면으로 구현한다.

## 6. 기대 효과 및 확장 가능성

### 6.1 해결하는 문제와 기대 효과

- **1차 스크리닝 시간 단축**: 3개 기관 사이트를 오가며 하던 특허·벤처확인·재무 조회를 기업명 입력 한 번으로 통합. 접수 물량이 많은 정책자금·보증 시즌의 병목 완화.
- **심층심사 질의서 자동 초안**: 반증 플래그가 곧바로 "무엇을 더 물어봐야 하는지"로 변환되어, 심사역이 백지에서 질의서를 쓰지 않아도 된다.
- **심사 소명 근거 확보**: 모든 수치·플래그에 원천값과 링크가 붙어 있어, 심사위원회·내부감사·국정감사에서 판단 근거를 그대로 제시할 수 있다.
- **심사 일관성·투명성**: 집계식과 규칙이 공개되어 심사역마다 다른 잣대를 쓰는 문제를 줄이고, 기관 차원의 심사 품질 관리가 가능해진다.
- **초기 기업에 불리하지 않음**: 데이터 부재를 저평가로 처리하지 않으므로, 유망한 초기 기업이 "기록이 적다"는 이유로 걸러지는 것을 방지한다.

### 6.2 받는 혜택 (사용자별)

- **심사역**: 조회·대조·질의서 작성 시간 절감, 놓치기 쉬운 모순(개인 명의 특허, 인증 만료 등) 자동 포착.
- **심사 기관**: 심사 근거 문서화·감사 대응 비용 절감, 심사 결과의 대외 신뢰성 제고.
- **피심사 기업(간접)**: 심층심사에서 무엇을 소명해야 하는지 미리 알 수 있어 준비 부담이 예측 가능해진다.

### 6.3 확장 가능성

- **평가 축 추가**: ① 활동성(momentum) — 채용 공고·정부 R&D 과제 수주 추이 등 시계열 신호를 4번째 축으로 ② 공신력 축에 이노비즈·메인비즈 등 인증 소스 추가.
- **비정형 데이터 대조(5.2 향후 적용)**: 자기서술 원문 입력 → LLM claim 추출 → 공개기록 교차검증.
- **기관 연동**: 여신·보증 심사 워크플로우 시스템(API)에 팩트시트·플래그를 주입, 심사표에 자동 첨부.
- **금융 외 영역 응용**: 공공조달 적격심사(입찰 참가기업 검증), 벤처투자조합·모태펀드 출자 심사, ESG·공급망 실사, M&A 예비실사에서의 대상기업 공개기록 스크리닝. 어느 경우든 "자기서술 vs 공개기록 대조 + 출처 역추적"이라는 구조는 동일하게 적용된다.

## 7. 재현 가능성과 감사 대응 (자유 항목)

- **완전 공개데이터**: 3개 소스 모두 정부·공공기관 무료 API. 유료 DB·크롤링에 의존하지 않아 라이선스·안정성 리스크가 없다.
- **결정론성**: 3축 집계·6규칙 반증은 규칙 기반 코드다. 같은 입력에 항상 같은 출력이 나오며, 집계식이 문서화되어 제3자가 검증할 수 있다.
- **생성형 AI의 경계**: LLM은 서술·문장화만 담당하고 점수에 관여하지 않으며, 호출 실패 시에도 서비스가 정상 동작한다.
- **기술 스택**: 백엔드 FastAPI(Python) — Render 배포 / 프런트엔드 React(Vite) — Vercel 배포 / 생성형 AI Anthropic Claude. 데모 기업 결과 캐싱으로 대회 URL 생존 구간 안정성 확보.
- **한계(투명 고지)**: 특허 조회는 현재 동명이인 보정이 제한적이며(출원인명 직접 검색), 투자이력 축은 공시 필드 제약으로 이진 플래그 수준이다. 리포트에 매칭 신뢰도와 함께 명시한다.
