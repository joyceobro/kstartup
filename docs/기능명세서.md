## 1. 개요

### 1.1 목적

재무제표가 없는 초기 벤처기업을 심사해야 하는 **기관 심사역**(기술보증기금·신용보증기금·정책금융기관·은행 기업여신·창업지원기관 서류심사역)에게, 공개데이터만으로 만든 **출처 역추적형 3축 팩트시트**와 **자기서술 vs 공개기록 모순 플래그**, 그리고 **심층심사 질의 문항 초안**을 제공한다.

### 1.2 핵심 설계 원칙 (구현 전반에 적용)

| 원칙 | 구현상 의미 |
|---|---|
| **Non-self-grading** | 점수·등급은 전부 규칙 기반 결정론적 집계(`core/scoring.py`, `core/falsify.py`). LLM은 점수를 만들거나 바꾸지 않는다. |
| **출처 부착** | 모든 축 점수에 `source` 필드(원천 API 명), 특허·벤처확인 원문을 응답에 포함 → 심사의견서 첨부·역추적 가능. |
| **데이터 부재 ≠ 감점** | 특허·재무 없음은 초기 기업의 정상 상태로 중립 표기. 반증 엔진은 "없음"이 아니라 "모순"을 잡는다. |
| **장애 격리** | 외부 API 실패·키 미설정 시 해당 축만 공백 처리하고 파이프라인은 계속 동작. LLM 실패 시 서술만 생략. |
| **결정론·재현성** | 동일 입력 → 동일 출력. 임계값·집계식을 본 문서와 코드에 공개. |

## 2. 시스템 구성

### 2.1 처리 흐름

```
[사용자] 기업명(+주소) 입력
   │
   ▼  GET /api/evaluate?company=…&refresh=false
[FastAPI · main.py]
   │
   ▼  core/pipeline.py  evaluate()
   │
   ├─ 캐시 히트(refresh=false & 파일 존재) ──────────► 캐시 JSON 반환
   │
   └─ 캐시 미스 → _evaluate_live()
        │
        ├─(1) 수집  collectors/venture.py  · patent.py · dart.py   [실패는 _safe()로 격리]
        │
        ├─(2) 개체 연결  core/normalize.py  resolve_entity()
        │        정규화 기업명 완전일치로 3소스 병합 → match_confidence 산출
        │
        ├─(3) 3축 결정론 집계  core/scoring.py  score_all()
        │
        ├─(4) 반증 엔진 6규칙  core/falsify.py  run_all()
        │
        ├─(5) 질의 문항 변환  core/falsify.py  to_interview_questions()
        │
        ├─(6) 투자자 매칭(부가 데모)  core/matching.py  match_vcs()
        │
        ├─(7) LLM 종합 서술  core/narrative.py  generate_narrative()   [실패 시 narrative=null]
        │        · summary 생성  · 질의 문항 기업 맥락 반영해 다듬기(ai_refined)
        │
        └─ 결과 JSON → data/cache/ 저장 → 반환
```

### 2.2 모듈 목록

| 모듈 | 역할 |
|---|---|
| `main.py` | FastAPI 앱, `/health`·`/api/evaluate`, CORS, 404/400 처리 |
| `core/pipeline.py` | 오케스트레이션 + 파일 캐싱 + 수집기 예외 격리(`_safe`) |
| `collectors/venture.py` | 벤처기업명단 조회 (`VentureAPIError`) |
| `collectors/patent.py` | KIPRIS 특허 조회 (`PatentAPIError`) |
| `collectors/dart.py` | OpenDART 고유번호·주요계정·기업개황 (`DartAPIError`) |
| `core/normalize.py` | 기업명 정규화, 개체 연결, 매칭 신뢰도 |
| `core/scoring.py` | 기술력·투자이력·공신력 3축 집계 |
| `core/falsify.py` | 반증 6규칙 + 질의 문항 시드 변환 |
| `core/narrative.py` | LLM 종합 서술 + 질의 문항 다듬기 (Gemini) |
| `core/matching.py` | 룰 기반 투자자·지원사업 힌트 (가상 시드) |
| `scripts/backfill_narrative.py` | 캐시된 데모 결과에 narrative 일괄 주입 (배포 전 1회) |

## 3. 데이터 소스 명세

### 3.1 특허 — KIPRIS Plus (기술력 축)

| 항목 | 내용 |
|---|---|
| 오퍼레이션 | `patUtiModInfoSearchSevice/getAdvancedSearch` (전체검색) |
| 인증 | `ServiceKey` 파라미터에 `KIPRIS_KEY` |
| 입력 | 출원인명(기업명), 권리상태, 출원일 범위, 특허/실용, `numOfRows` |
| 출력(활용) | `totalCount`, `registerStatus`(등록/공개/소멸/무효/거절), `ipcNumber`, `applicationDate`, `applicantName` |
| 제약 | `CommonSearchApplicantInfo`(특허고객번호=PersonNumber 조회)는 계정 미승인 → **기업명을 출원인으로 직접 조회하는 폴백**으로 동작. 동명이인 보정 제한적. 개발단계 계정 트래픽 한도 → 상위 캐싱 필수. |

### 3.2 벤처기업명단 — 공공데이터포털 odcloud (투자이력·공신력 축)

| 항목 | 내용 |
|---|---|
| 데이터셋 | data.go.kr `15084581` (중소벤처기업부) / `uddi:{스냅샷 UUID}` |
| 인증 | `serviceKey` — Encoding/Decoding 키 혼입 방지 위해 `urllib.parse.unquote()` 1회 적용 후 전송 |
| 입력 | `cond[업체명::LIKE]=검색어` (부분일치), `page`, `perPage` |
| 출력(활용) | 업체명, 대표자명(마스킹 `이**`), **벤처확인유형**(벤처투자/연구개발/혁신성장/예비벤처), 지역, 주소, 업종분류(기보), 업종명(11차), 주생산품, **벤처유효시작일·종료일**, 벤처확인기관, 신규_재확인 |
| 제약 | 원 기획이 기대한 "투자유치 금액·시기" 필드가 데이터셋에 없음 → 투자이력 축은 "벤처투자유형" **이진 플래그**로 근사. 스냅샷 UUID는 주기적 갱신 필요. |

### 3.3 재무·기업개황 — OpenDART (보조 재무 축)

| 항목 | 내용 |
|---|---|
| 오퍼레이션 | `corpCode.xml`(고유번호 전체, 최초 1회 → `data/corp_code.xml`), `fnlttSinglAcnt.json`(단일회사 주요계정), `company.json`(기업개황) |
| 인증 | `crtfc_key` = `DART_KEY` |
| 입력 | 기업명 → `corp_code`(8자리) 매핑 → 사업연도(전년도) |
| 출력(활용) | 주요 재무계정, 기업개황의 `bizr_no`(사업자번호)·`jurir_no`(법인번호), `corp_name`, `est_dt`, `induty_code` |
| 제약 | 초기 기업 대부분 DART 미등록. `status=="013"`(데이터 없음)은 에러가 아니라 **D1 중립 표기** 대상. 사업자·법인번호는 DART 매칭 시에만 부가 노출(필수 매칭 조건 아님). |

## 4. 기능 명세

> 임계값은 `core/falsify.py`·`core/scoring.py` 상단에 상수로 공개되어 있으며, 실데이터 확보 시 조정 가능한 근사치다.

### F-01 · 기업 조회 진입점

- **입력**: `company`(문자열, 필수), `refresh`(불리언, 기본 `false`).
- **처리**: `company` 공백 제거 후 비면 400. 정규화 기업명으로 캐시 파일 경로 결정 → `refresh=false`이고 캐시 존재 시 즉시 캐시 반환, 아니면 라이브 수집.
- **404 조건**: `profile.match_confidence == "unmatched"` **그리고** 기술력 `total_count == 0` (= 3소스 어디서도 못 찾음).
- **출력**: §5 응답 스키마.

### F-02 · 개체 연결 및 매칭 신뢰도 (`core/normalize.py`)

- **정규화**: `주식회사`, `(주)`, `㈜`, `유한회사` 등 법인격 표기 + 공백 제거.
- **매칭**: 각 소스 후보 리스트에서 정규화 기업명 **완전일치** 1건 선택 (venture=`업체명`, dart=`corp_name`).
- **`match_confidence`**:
  | 값 | 조건 |
  |---|---|
  | `verified` | 벤처확인 + DART 양쪽 완전일치 |
  | `name_only` | 한 쪽만 일치 |
  | `unmatched` | 둘 다 불일치 |
- **식별자**: DART 매칭 시 기업개황에서 `bizr_no`·`jurir_no`를 `profile.identifiers`로 노출(실패해도 매칭 유효).

### F-03 · 기술력 축 (`score_technology`)

- **입력**: 특허 `items`(권리상태·IPC·출원일·출원인명), 벤처확인유형.
- **지표**: `total_count`, `registered_count`(권리상태=등록), `active_count`(등록+공개), `ipc_class_count`/`ipc_classes`(IPC 앞 4자리 대분류 집합), `is_rnd_venture_type`(벤처확인유형=연구개발유형).
- **tier 규칙**:
  | tier | 조건 |
  |---|---|
  | `데이터없음` | `total_count == 0` |
  | `높음` | `registered_count ≥ 5` 또는 `total_count ≥ 20` |
  | `보통` | `registered_count ≥ 1` 또는 `total_count ≥ 5` |
  | `낮음` | 그 외 |
- **source**: `KIPRISPlus patUtiModInfoSearchSevice/getAdvancedSearch`.

### F-04 · 투자이력 축 (`score_investment`)

- **입력**: 벤처확인유형.
- **tier 규칙**: 벤처확인 없음 → `정보없음` / 유형이 `벤처투자유형` → `있음` / 그 외 → `없음`.
- **지표**: `has_venture_investment_type`, `venture_confirm_type`.
- **비고**: 공시에 금액·시기 필드가 없어 이진 플래그로 근사(설계 결정 2026-08-20).
- **source**: `data.go.kr 중소벤처기업부_벤처기업명단(15084581)`.

### F-05 · 공신력 축 (`score_credibility`)

- **입력**: 벤처확인 보유 여부, `벤처유효종료일`, 기준일(`as_of`, 기본 오늘).
- **tier 규칙**:
  | tier | 조건 |
  |---|---|
  | `정보없음` | 벤처확인 없음 |
  | `확인불가` | 유효종료일 파싱 불가 |
  | `만료` | `days_left < 0` |
  | `만료임박` | `0 ≤ days_left ≤ 90` |
  | `유효` | `days_left > 90` |
- **지표**: `has_certification`, `cert_type`, `cert_agency`, `valid_from`, `valid_until`, `days_until_expiry`.
- **알려진 제약**: 이노비즈·메인비즈 API가 확정 소스에 없어 벤처확인 단일 소스로만 판정.

### F-06 · 보조 재무 (DART, `check_d1_no_financials`에서 표기)

- DART 미등록 또는 `status=="013"` → 감점 없이 "초기단계, 공시의무 없음" 중립 표기 + 재무자료 요청 문항(D1).
- DART 존재 시 주요계정을 참고 정보로 포함.

### F-07 · 반증 엔진 6규칙 (`core/falsify.py`)

각 규칙은 `{rule, level, message, question}`을 반환(미해당 시 없음). `level` ∈ `확인필요` / `중립` / `판단보류`. **감점이 아니라 심층심사 지목**이다.

| 규칙 | 트리거 조건 | level | 지목 요지 |
|---|---|---|---|
| **A1** 기술 근거 | 벤처확인유형=연구개발유형 **AND** (특허 0건 **또는** 최근 출원일로부터 **24개월**↑ 경과) | 확인필요 | R&D 성과물·특허 계획 확인 |
| **A2** 특허 법인 귀속 | 특허 존재 **AND** 출원인명이 법인명과 다른 비율 **≥ 50%** | 확인필요 | 개인→법인 양도·전용실시권 자료 |
| **C1** 투자 후 활동 | 벤처확인유형=벤처투자유형 **AND** 유효시작일 이후 **12개월**↑ 경과 **AND** 그 기간 신규 출원 0건 | 확인필요 | 투자금 집행·사업화 성과 |
| **C2** 인증 유효성 | 벤처유효종료일이 이미 만료 **또는 90일 이내** 만료 | 확인필요 | 재확인 신청 상황·유효 인증서 |
| **D1** 재무 자료 | DART 미확보 또는 `status 013` | 중립 | 최근 3개년 재무제표/결산서 요청 |
| **D2** 기초 자료 | 벤처확인·특허·DART **세 축 전부 공백** | 판단보류 | 사업자등록증·매출 증빙 등 일체 요청 |

- **임계값 상수**: `A1_STALL_MONTHS=24`, `A2_INDIVIDUAL_RATIO=0.5`, `C1_STALL_MONTHS=12`, `C2_EXPIRY_WARNING_DAYS=90`.

### F-08 · 심층심사 질의 문항 변환 (`to_interview_questions`)

- 각 플래그의 `question`을 `{rule, title, level, question}`로 재구성. `title`은 규칙별 고정 라벨(A1=기술 근거 확인, A2=특허 법인 귀속 확인, C1=투자 후 활동 확인, C2=인증 유효성 확인, D1=재무 자료 요청, D2=기초 자료 요청).
- 심사역이 심층심사 질의서에 그대로 붙여 쓸 수 있는 완결 문장으로 출력.

### F-09 · LLM 종합 근거 서술 (`core/narrative.py`)

- **모델**: `gemini-3.6-flash` (env로 교체 가능). OpenAI 호환 `chat.completions`, `response_format=json_object` + 프롬프트 스키마 강제, 실패 시 일반 모드 재시도 → 중괄호 슬라이스 폴백.
- **입력**: 결정론 결과에서 추린 원천값(기업명, 매칭 신뢰도, 벤처확인 원문, 3축 tier·지표·source, 플래그 메시지)만. 토큰 절약 + 프롬프트 인젝션 표면 축소.
- **출력**:
  1. `summary` — 심사의견서 첨부용 건조한 실무체 국문 3~5문장. 집계된 tier·수치를 **인용만**.
  2. `questions[]` — F-08 템플릿 문항을 기업 실제 상황(만료일·출원 시점 등) 반영해 한 문장으로 다듬음 → 해당 `interview_questions` 항목을 rule 단위로 덮어쓰고 `ai_refined: true` 표시. 원본은 fallback 보존.
- **시스템 프롬프트 하드 제약**: 점수·등급·투자적격 재판정 금지 / 입력에 없는 사실(매출·고용·경쟁사) 생성 금지 / 데이터 부재를 결점으로 서술 금지 / 불확실은 "확인 필요"로 명시.
- **안전장치**: `LLM_API_KEY` 미설정·SDK 없음·API 오류 → `narrative: null` 반환, 나머지 결정론 결과는 그대로.

### F-10 · 투자자·지원사업 힌트 (부가 데모, `core/matching.py`)

- **명시적 데모**: `data/vc_seed.json`은 실제 투자 성향 조사가 아닌 **가상 시드**. 응답에 `is_demo_data: true`·`note` 포함.
- **태그 유도(결정론)**: 단계(벤처확인유형 → 예비창업/투자유치이력있음/초기(투자전)), 업종(업종분류(기보)·업종명(11차)), 테마(특허 IPC 앞 4자리 → 기술 테마 매핑).
- **매칭 점수**: 단계 일치 +2, 업종 겹침당 +2, 테마 겹침당 +1. 상위 5개 반환, 각 항목에 `reasons[]`.

### F-11 · 캐싱 및 장애 격리

- **캐시**: `use_cache=true`(기본) & `refresh=false` & `data/cache/<정규화명>.json` 존재 → 파일 그대로 반환. 라이브 조회 결과는 항상 파일로 기록.
- **격리**: `_safe()`가 `VentureAPIError`·`DartAPIError`·`PatentAPIError`·`requests.RequestException`만 흡수하고 기본값 대체. 그 외 예외(코딩 버그 등)는 전파.
- **배포 대비**: 데모 기업은 사전 캐싱 + `backfill_narrative.py`로 narrative까지 구워 배포 URL 생존 구간(2026-09-07~09-11)에 외부 API 없이도 응답.

## 7. 비기능 명세

| 항목 | 내용 |
|---|---|
| **가용성** | Render free는 15분 유휴 시 슬립(콜드스타트 ~50초) → 외부 모니터 2종(cron-job.org + UptimeRobot) 5분 간격 `/health` 핑으로 상시 웜 유지. 데모 결과 파일 캐시로 외부 API 장애와 무관하게 응답. |
| **재현성** | 3축·6규칙은 규칙 기반 코드, 임계값 공개. 동일 입력 → 동일 출력(단, `as_of` 기본값이 오늘이라 날짜 의존 규칙 C2/A1은 경과일 표기가 갱신됨). |
| **보안** | API 키는 `.env`/배포 대시보드에만, git 미추적. LLM 입력은 원천값만 추려 전송. CORS는 배포 시 `CORS_ORIGINS`로 좁힘. |
| **성능** | 캐시 히트 응답 < 1초. 라이브 조회는 3개 외부 API 호출 합산(수 초). |
| **국제화/접근성** | 국문 단일. 데스크톱 웹 우선(모바일 반응형은 향후). |
